`VideoProbe` copies the MODE 7 setup from `video_power_on_reset`. This is an
upstream emulator fixture, not measured physical power-on state. Public register
writes establish it without booting MOS. The no-dummy-raster case advances
39,872 CPU cycles, writes R8=0, then advances 64, preserving the upstream
schedule. A local fixture guard requires a VSYNC edge to have occurred so a
stopped timing engine cannot satisfy the negative assertion vacuously.

Other cases retain their source writes, elapsed intervals and selected
VSYNC/counter assertions. Beebjit's timer callbacks and explicit
`video_advance_crtc_timing` are mapped to our public `Tick`. Read-only reflection
observes the corresponding state. Internal timer optimisation, rendering-active
and frame-accounting assertions specific to beebjit are not ported. Clock-edge
alignment and internal-state correspondence must be audited when a case fails.
Do not adjust the expected values to make the emulator pass.

### T8 adaptation

We replay the six `$FE20` writes of T8's `.sw` loop, alternating `$8A/$88` at
11 CPU-cycle intervals. We do not run BASIC, its assembler, the CPU instructions,
VSYNC polling, keyboard exit or the full 128-line raster loop. CRTC setup uses
the upstream MODE 4 fixture plus T8's R6=26, R8=0 and display-start=$2800.
The cursor is disabled. Memory is filled with the interior test band's $FF
bytes; ruler rows and presentation text are omitted.

Two frames are allowed to settle, then an interior scanline is selected from
beam coordinates. Selection does not depend on expected pixels or success.
The same writes run once at each clock phase. The raw framebuffer is segmented
into red bitmap regions and non-red teletext regions. We require exactly three
boxes, each 88 pixels wide (5.5 cells at this renderer's 16 pixels/cell), with
88-pixel red gaps. Start position is deliberately not asserted, consistent with
the source's warning about horizontal phase. Glyph fill is not compared.

The geometry conversion is a harness convention; 88 framebuffer pixels is not
a claim about the resolution of the original composite capture. No stored
jsbeeb reference PNG, image generated by our emulator or search for a passing
pixel alignment is used as expected output. Framebuffer/reflection naming and
scale are adaptation dependencies. This checks ULA output switching with CRTC
scanout, not complete CPU/VIA/raster timing or a pixel-perfect SAA5050 model.

## Missing evidence / exclusions

The three Unverified CRTC cases have external code provenance but no established
physical-machine result. The distinction is intentional. No hardware evidence
has been integrated for the other video areas listed in README.md. Passing
this small suite alone would not establish complete Model B video accuracy.

## Adapter audit and corrections — 15 September 2026

Before changing production code, the retained source schedules were checked
against their original functions. The pinned beebjit engine passed the complete
`video_test_6845_corner_cases`, `video_test_no_dummy_raster` and
`video_test_vsync_mux` functions. Our selected register writes, elapsed cycles
and assertions match the corresponding portions of those tests. Its internal
counter/timer assertions remain upstream-only, rather than being forced onto
our implementation.

The local T8 register waveform and measurement region were also replayed against
the pinned jsbeeb Video engine. Both phases produced three 88-pixel boxes and
88-pixel gaps. The adapter changes framebuffer red from our ARGB representation
to jsbeeb's ABGR representation; it preserves the measured widths, clock phases
and write intervals. This validates the software adaptation, not a new physical
Model B measurement. Reproduction commands and small runners are retained in
[Validation](Validation/README.md).

Confirmed implementation discrepancies were corrected:

- The VSYNC elapsed counter previously wrapped at fifteen and could never reach
  its decoded sixteen-line width. Pulse transitions now use the advanced CRTC
  counters at line and half-line boundaries.
- R8 previously changed interlace mode without selecting the corresponding
  independent line/half-line pulse. Separate pulse state now permits immediate
  output changes without restarting a pulse.
- ULA output selection previously affected only whole characters. The SAA5050
  output is now retained while bitmap output is selected, allowing a write
  between CPU cycles to repaint only the second half of the current 1 MHz cell.

All six original cases pass with unchanged expectations. The three upstream
CRTC cases without independent hardware results remain Unverified despite
agreement with beebjit. The T8 evidence remains qualified to one Master.

Three additional `Unverified/SaveState/` cases compare continued execution,
VSYNC edges and serialized state/framebuffers before and after restoration.
They are local software regression checks for the new state, not physical BBC
measurements. All pass, bringing VIDEO_TESTS to nine passing cases.

Related regression suites retain their previous results: sound 3/3, memory
66/66, VIA 65/76 and BBC timing 77/89. VIA and timing failure diagnostics are
unchanged. The user also reported correct displays in Yie Ar Kung Fu, Pole
Position, Phoenix, Repton, Elite and Snapper on 15 September 2026; this report
is visual regression evidence, not independent hardware validation.

# VIA evidence audit

## SourcedBBC/jsbeeb/* — external results

Original author: Scarybeasts (Chris Evans), as credited by jsbeeb. Adapter source:
[`tests/integration/via.js`](https://github.com/mattgodbolt/jsbeeb/blob/d74d9043e83b981a4a3fe1d621f309e8bf083a9c/tests/integration/via.js).
Revision: `d74d9043e83b981a4a3fe1d621f309e8bf083a9c`. The file traces these
programs to [jsbeeb issue 179](https://github.com/mattgodbolt/jsbeeb/issues/179).
GPL-3.0 licence and unchanged upstream source are retained in `../External/jsbeeb`.

Imported IDs: **VIA.AC1–AC7, VIA.I1, VIA.PB2, VIA.T12**. Each selected program
contains a `REAL BBC` result statement and an explicit expected array. The
upstream report is the hardware evidence: we have not independently rerun these
on a physical BBC, and exact chip date codes/electrical conditions are not given.

`via-cases.json` retains the assembly, source line, instruction bytes and original
expected array for each ID. Rebuild it with:

```sh
python3 Tests/External/extract_via.py
```

The extractor accepts only the instructions used in these straight-line cases
and fails on unsupported syntax. R% stays at `$0100`, matching jsbeeb. Code is
relocated to `$2000`; the selected programs have no location-dependent branches.
Only the BASIC presentation/CALL wrapper is omitted. The final RTS is not
executed because there is no BASIC call frame. Timer and port accesses execute
through our production NMOS CPU, 1 MHz bus and User VIA. We reset both VIAs,
disable synthetic System VIA VSYNC and firmware hooks, and do not boot MOS.
These setup differences are adaptation limitations, not measured hardware facts.

No expected bytes are generated by our emulator. Failures can arise in the CPU,
bus, VIA or adapter; they are not isolated VIA diagnoses.

## Unverified/* — all 66 original local cases

Every original case from `CommonTests.cs`, `SystemTests.cs` and `UserTests.cs`
is explicitly prefixed `Unverified/`. **None has independently verified BBC
result data attached.** This includes timers, IRQs, ports, keyboard, IC32, ADC,
VSYNC, mirrors and state restoration. The WDC W65C22 reference previously cited
is documentation for a different chip generation, not evidence that these cases
were measured on a BBC's NMOS 6522. State restoration is an emulator regression.

Earlier results of 57 passes/9 failures remain historical local assertions only.
The nine failures must not be described as nine proven hardware defects.

## Not imported / not claimed

- C1–C3 and the Master C4 result are marked checked on a BBC Master upstream;
  they are not silently used as Model B evidence.
- C5 explicitly requests a real-BBC check upstream.
- T23 is skipped upstream and has external-pin qualifications.
- Remaining BASIC/IRQ/loop-based cases need faithful additional adapters.
- This is not the full jsbeeb VIA suite and does not certify all VIA modes.

## Audited baseline — 14 September 2026

- Sourced BBC: **10 cases, 8 passed, 2 failed** (VIA.AC6 and VIA.AC7).
- Unverified local: **66 cases, 57 passed, 9 failed**.
- Full run: 76 cases, 65 passed, 11 failed; exit code 1.

The sourced failures differ at ACR changes around expiry. Expected arrays remain
unchanged; the adapter and emulator need further diagnosis before a core fix.
